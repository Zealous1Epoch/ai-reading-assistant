一、项目概览

1.1 这是什么项目

一款面向深度阅读者的 AI 辅助阅读工具，帮助用户高效理解和分析书籍内容。 上传 PDF/EPUB/TXT 格式的书籍后，AI 会自动切分章节、生成摘要和关键词； 支持三种模式的 AI 对话（当前章节 / 整本书 / 多书对比），并提供六个分析工具（总结、背景调研、读书十问、思维导图、书籍推荐、芒格辩论法）。

核心能力

  • AI 辅助章节自动切分
  • ChromaDB 向量语义搜索
  • 三模式 RAG 对话
  • 7 个深度分析工具
  • 知识图谱 HTML 导出
  • 思维导图全屏放大
  • 收藏夹 + 导出
  • 全文关键词精确搜索
  • 层级目录 TOC 展示

解决的问题

  • 书太厚没时间精读
  • 读完后记不住要点
  • 想对比多本书观点
  • 缺乏批判性思考视角

支持格式

  • PDF（含扫描版 OCR 降级）
  • EPUB（按 spine 阅读顺序）
  • TXT（纯文本）
  • 批量并行上传

2.2 服务层（Services）— 核心业务逻辑

BookProcessor（书籍处理器 — 最核心的服务）

位置: backend/app/services/book_processor.py (530行)

单例模式，初始化时创建 ChromaDB PersistentClient 和 book_chapters collection。

主流程 process_book()：

提取文本
PDF/EPUB/TXT → AI识别目录
前5000字 → 正则降级
6组模式 → 按目录切分
三级定位 → 存入ChromaDB
向量化 → 返回
BookAnalysisResult
方法功能关键技术点
extract_text_from_pdf() PyMuPDF 提取 PDF 文本 自动检测扫描版（<20字/页）→ OCR降级；渲染阶段加锁（fitz非线程安全）
extract_text_from_epub() EbookLib 提取 EPUB 文本 按 spine 阅读顺序遍历，保留块级换行，去除行内HTML标签
detect_toc_by_ai() DeepSeek 识别目录结构 取前5000字，System Prompt 内置示例，要求返回JSON数组
_fallback_toc_detection() 正则降级匹配章节 6组正则模式，去重取正文位置（非目录区），上限30条
split_by_toc() 按目录边界切分章节 三级匹配：行首精确→子串→宽松；自动插入前置章承接首页内容
search_chapters() 语义搜索 Chromadb query，支持单书/多书 where 过滤，top-N返回
store_chapters_to_chroma() 向量化批量写入 metadata 包含书名/章节号/字数，供后续过滤和展示

AnalysisService（AI 分析服务）

位置: backend/app/services/analysis_service.py (250行)

方法功能关键技术点
analyze_chapter() 深度分析章节 结构化JSON输出（论点论据+杠精视角+对话总结），要求AI发现隐含假设和逻辑漏洞
stream_chat() 流式对话（核心） AsyncGenerator + SSE；System Prompt根据内容类型自动切换风格（学术/通俗）；内置 Markdown 禁用指令
generate_chapter_summary() 章节摘要+关键词 100-200字摘要 + 3-5个关键词，JSON格式输出
quick_analysis() 快速分析 三种模式：总结(100字)/要点(3-5条)/批判(1-2个问题)

两种 LLM 实例：self.llm（非流式，temperature=0.7）和 self.streaming_llm（流式），均延迟初始化。

AIService（通用 AI 服务 — 旧版，被 AnalysisService 取代）

位置: backend/app/services/ai_service.py (58行) — 提供 chat / summarize / answer_question 三个基础方法。新版代码主要使用 AnalysisService。

DocumentService（文档处理服务）

位置: backend/app/services/document_service.py (83行) — MIME 类型检测 + 扩展名降级 + PDF 元数据提取。新版文本提取逻辑已合并到 BookProcessor 中。

模型关键字段用途

四、核心数据流

4.1 书籍上传与解析流程（最复杂的流程）

异步三阶段上传链:
  Phase 1 — POST /books/upload   → 保存文件到 uploads/ → 返回 {book_id, filename, format}
  Phase 2 — POST /books/analyze/{book_id} → BackgroundTasks 异步分析（文本提取→目录识别→章节切分→向量存储）
  Phase 3 — GET /books/status/{book_id} → 前端轮询 {status, ocr_progress: {current, total}}
            → status=completed 时 GET /books/analysis/{book_id} 获取结果

用户拖拽/选择文件
  │
  ▼
前端: 文件格式校验(.pdf/.epub/.txt) → FormData
  │
  ▼
POST /books/upload（单本快速返回）→ POST /books/analyze/{book_id}（异步分析）
  或 POST /books/batch-upload（多本并行，部分失败不阻塞）
  │
  ▼
后端 book_processor.py:
  │
  ├── 1. 保存原始文件 → backend/uploads/{uuid}.{ext}
  │
  ├── 2. extract_text(file_path) → 自动检测格式
  │     ├─ PDF:  PyMuPDF 逐页提取 → 检测扫描版(平均<20字/页)
  │     │         └─ 是扫描版 + Tesseract已安装 → OCR（4线程并行，渲染加锁）
  │     ├─ EPUB: EbookLib 按 spine 顺序遍历 → HTML→纯文本（保留块级换行）
  │     └─ TXT:  直接 utf-8 读取
  │
  ├── 3. detect_toc_by_ai(text[:5000]) → DeepSeek API
  │     ├─ System Prompt: "你是专业的书籍结构分析助手"
  │     ├─ 要求返回 JSON: [{title, level, pattern}, ...]
  │     └─ 失败 → 返回空列表[]
  │
  ├── 4. _fallback_toc_detection(full_text) ← AI 失败时的保底方案
  │     ├─ 6组正则: 第X章/Chapter X/Part X/Section X/X.X/序言附录等
  │     ├─ 去重策略: 相同章节号保留正文位置(靠后)，非目录区(靠前)
  │     └─ 上限30条
  │
  ├── 5. split_by_toc(full_text, toc_items)
  │     ├─ 三级匹配定位章节边界:
  │     │   L1: 行首精确匹配 + 行尾终止(排除正文中的引用)
  │     │   L2: 子串匹配（取最后出现位置=正文位置）
  │     │   L3: 宽松匹配（允许标题前后空白）
  │     ├─ 自动插入前置章（首页/目录等内容不被丢弃）
  │     └─ 过滤: word_count < 50 的过短章节
  │
  ├── 6. store_chapters_to_chroma(book_id, chapters, book_title)
  │     ├─ collection.add(ids, documents, metadatas)
  │     └─ metadata: {book_id, book_title, title, chapter_index, word_count}
  │
  └── 7. 返回 BookAnalysisResult → 写入 data/books_index.json（content 字段置空，仅存元信息）
        └─ 前端轮询 /books/status/{id} → completed 后获取分析结果 → 更新 books state

4.2 三模式对话流程（最常用的流程）

用户输入消息 → 按下发送
  │
  ├── 📖 当前书籍模式 (chatMode='book'):
  │     请求: POST /analysis/chat/stream
  │           {message, book_id, chat_history}
  │     后端:
  │       1. ChromaDB.query(message) → 语义搜索 top-5 相关章节
  │       2. 拼接章节片段作为上下文
  │       3. DeepSeek 流式生成 → SSE data: {"content":"..."}
  │     特点: RAG 增强，覆盖全书相关内容，适合通读
  │
  └── 📚 综合阅读模式 (chatMode='cross'):
        请求: POST /analysis/chat/stream
             {message, selected_book_ids, chat_history}
        后端:
          1. ChromaDB.query(message, where={book_id: {$in: selected_book_ids}})
              → 跨书语义搜索 top-5 最相关章节
          2. 拼接多书内容作为上下文对比
          3. DeepSeek 流式生成 → SSE + 多书来源标注
        特点: 跨书对比分析，适合主题研究

SSE 数据格式:
  data: {"content":"这是流式"}     ← 逐 token 推送
  data: {"content":"生成的"}
  data: {"content":"回答内容"}
  data: {"sources":[...]}          ← 仅在整本书/综合阅读模式出现
  data: [DONE]                     ← 结束标记

4.3 AI 工具流程

用户点击工具卡片
  │
  ├── 需要输入的工具（总结 / 芒格辩论 / 思维导图）:
  │     cards → input → 用户输入 → loading → result
  │
  └── 无需输入的工具（背景调研 / 读书十问 / 知识图谱 / 书籍推荐）:
        cards → loading → result
  │

五、关键技术与设计决策

#决策选型原因
1 章节切分策略 AI 优先 + 正则降级 AI 识别准确但可能失败，正则保底确保永远有章节可用
2 AI 目录识别范围 仅看前 5000 字 省 Token 成本；目录通常在书籍开头
3 扫描版 PDF 处理 自动检测 → Tesseract OCR 平均每页 <20 字符触发 OCR；每页渲染加锁解决 fitz 线程安全问题
4 去重策略（目录vs正文） 取正文位置（靠后） 目录区章节标题出现早，正文标题出现晚，取后者作为切分边界
5 章节正文存储 ChromaDB 存全文，JSON 仅存元信息 前端按需加载章节内容，JSON 文件保持轻量
6 前端架构 无构建步骤（Babel Standalone） 简化部署，不需要 Node.js 构建链；适合小型前端
7 流式对话协议 SSE（Server-Sent Events） 比 WebSocket 简单，逐 token 推送，前端 Fetch API + ReadableStream 消费
8 对话历史策略 三模式独立存储 不同场景的上下文不混淆，切换模式不影响已有对话
9 收藏去重 question + answer 联合判断 相同问答不重复收藏，localStorage 持久化
10 服务实例化 单例模式（模块级实例） LLM 和 ChromaDB 客户端开销大，全局复用
11 LLM 温度 书处理器 0.1 / 分析服务 0.7 目录识别需高确定性；对话分析需一定创造性
12 上下文窗口 单章 10000 字 / RAG top-5 片段 思维导图模式扩至 12000 字以支持六级深度；DeepSeek 上下文 64K
13 思维导图 PNG 导出 放弃 → 改为全屏悬浮弹窗 offscreen canvas+SVG 导出遇到 CJK 字体处理、getBBox 返回 0 等连锁问题 10+ 次迭代无解；放大直接查看更实用
14 思维导图层级 六级深度（书名→章节→主题→论点→论据→引文/数据） 初始4级仅到主题层太简略，需深入到具体论据、案例、引文才能体现论证逻辑链
15 AI 前言清洗 前后端双重防护 后端 Prompt 约束「第一行必须是 # 开头」+ 前端 cleanMindmapData() 定位第一个 \n# 切除前文；单层不可靠
16 收藏数据结构扩展 增加 type 字段（qa / tool） 工具结果收藏需区分来源类型、toolId、toolLabel；导出时按 type 格式化标题行
17 上传处理链路 异步三阶段（upload → analyze → poll status） 大文件处理耗时长（OCR 2-5s/页），同步等待超时；异步解耦后前端轮询进度（含 OCR 页数反馈）
18 知识图谱输出格式 后端组装完整 HTML 页面 AI 返回结构化文本 → 后端解析（章节/摘录/批注/关键词/推荐）→ 组装锌色系 HTML；前端 iframe 预览 + 下载

六、部署架构

Docker 容器化部署（Railway）

# Dockerfile 核心步骤
FROM python:3.11-slim-bookworm
RUN apt-get install -y libmagic1          # python-magic 的 C 依赖
COPY backend/requirements.txt ./
RUN pip install -r requirements.txt
COPY backend/ ./backend/                   # 后端代码
COPY frontend/ ./frontend/                 # 前端静态资源
CMD uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
组件配置
基础镜像python:3.11-slim-bookworm（轻量 Debian）
系统依赖libmagic1（MIME 类型检测）
Python 依赖FastAPI, LangChain, PyMuPDF, EbookLib, ChromaDB, Pydantic 等
端口${PORT:-8000}（Railway 注入 PORT 环境变量）
前端服务FastAPI 直接挂载 StaticFiles + FileResponse，无需 Nginx
可选依赖Tesseract OCR（未预装，按需 apt install）
